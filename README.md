# ПОС — преподавательская оценка студентов

Тараненко Константин Александрович, БПИ255. КПО, домашнее задание №2.
C# / .NET 8. Консольное приложение для одного курса и одного рубрикатора.

## Запуск

Требуется .NET SDK 8. При первом восстановлении пакетов нужен доступ к NuGet.

```sh
dotnet build Pos.sln -m:1
dotnet test Pos.sln -m:1
dotnet run --project src/Pos.Console
```

В меню можно добавить студентов и критерии, увидеть списки, поставить или исправить
оценку, посмотреть оценки студента, отменить оценку, получить итог и экспортировать
итоги всех студентов в CSV. Критерий выбирается по номеру из списка, студент — по
своему уникальному номеру. Повторное выставление заменяет оценку, отмена удаляет её.
Некорректный ввод выводит сообщение и возвращает управление пользователю.
Дробные числа допускают точку и запятую. Конец входного потока завершает программу.

Сквозная демонстрация без ручного ввода:

```sh
dotnet run --project src/Pos.Console -- --demo exports/demo.csv
```

Она создаёт двух студентов и критерии с разными максимумами, выставляет оценки,
показывает отказы для балла 12/10 и неизвестного критерия, исправляет и отменяет
оценку, восстанавливает её, рассчитывает итоги и сохраняет CSV. Анна получает 8.00,
Борис — 2.00; строгая стратегия для Бориса отказывает из-за отсутствующего экзамена.

## Правила и расчёт

У критерия положительный максимум и вес в (0; 1]. Сумма весов при добавлении не может
превышать 1; расчёт разрешён только при сумме ровно 1. Промежуточный рубрикатор
может быть незавершённым, чтобы вводить критерии последовательно через меню.
Повторяющиеся названия критериев (без учёта регистра) и номера студентов запрещены.
Критерии после создания неизменяемы: изменение максимума не обесценит старые оценки.

Итог по шкале 0–10:

`10 × Σ(балл / максимум × вес)`.

Округление до двух знаков выполняется один раз, после суммы, половины округляются
от нуля. Используется `decimal`. Для ДЗ 16/20 с весом 0.4 и экзамена 8/10 с весом 0.6
получается `10 × (0.8 × 0.4 + 0.8 × 0.6) = 8`.

Два доступных правила: «Пропуски = 0» и «Все оценки обязательны». В первом случае
пропуски не перераспределяют веса; во втором итог недоступен, пока нет всех оценок.
Итог не хранится в сущности: после исправления или отмены он рассчитывается заново.
Выводится также число заполненных критериев, чтобы отличать ноль от отсутствия оценки.

## Карта DDD

- Ubiquitous Language: `Student`, `Criterion`, `Rubric`, `Evaluation`, `GradeBook`,
  `FinalScore` соответствуют студенту, критерию, рубрикатору, оценке, ведомости и итогу.
- Entity: `Student` определяется номером `StudentId`, `Criterion` — `Guid`. Два студента
  с одинаковым ФИО и разными номерами являются разными студентами.
- Value Object: `StudentId` сравнивается по нормализованному значению; `Evaluation`
  неизменяема и сравнивается по содержимому, исправление создаёт новое значение.
  `FinalScore` — значение результата, а не отдельная сохраняемая сущность.
- Агрегат `Rubric` охраняет уникальность критериев и суммарный вес; критерии выдаются
  только для чтения. Агрегат `GradeBook` принадлежит одному студенту и хранит не более
  одной оценки по критерию. Его `Set` сначала ищет критерий в рубрикаторе и проверяет
  диапазон, затем изменяет состояние. Неудачная правка сохраняет старую оценку.
- `Student` — отдельный агрегат; Application проверяет его существование перед
  обращением к ведомости. Ведомость создаётся лениво и связана со студентом по ID.
- Repository: `IStudentRepository`, `IGradeBookRepository`, `IRubricRepository` — порты
  Application; реализации находятся в Infrastructure. Домен хранение не выполняет.
- Domain Service `FinalScoreService` объединяет правила рубрикатора, оценки ведомости
  и стратегию итога. Также отклоняет ведомость, относящуюся к другому рубрикатору.

## Архитектура: Ports and Adapters

```text
Pos.Console -> Pos.Infrastructure -> Pos.Application -> Pos.Domain
     |                                  ^
     +---------- composition root ------+
```

`Pos.Domain` не имеет ProjectReference и пакетов: только модель и расчёт.
`Pos.Application` зависит только от Domain: порты и сценарии `PosFacade`.
`Pos.Infrastructure` реализует репозитории в памяти и CSV-адаптер, зависит от Application.
`Pos.Console` — входной адаптер и composition root: собирает реальные зависимости
через Microsoft.Extensions.DependencyInjection, читает ввод и печатает результат.
UI не рассчитывает оценки и не пишет CSV самостоятельно. Транзитивные ссылки
позволяют composition root видеть все типы, внешние слои не нужны домену.

В DI используются singleton-репозитории: одна сессия приложения видит общее состояние.
Контейнер проверяет граф зависимостей при сборке. `IResultExporter` позволяет заменить
CSV другим экспортом; тест с fake-экспортёром проверяет эту границу без файлов.

## Три паттерна GoF

| Группа | Паттерн и место | Для чего |
|---|---|---|
| Порождающий | Builder, `RubricBuilder` | Поэтапная сборка полного рубрикатора с проверкой дубликатов и суммы весов в `Build`; используется в демо и тестах |
| Структурный | Facade, `PosFacade` | Объединяет репозитории, расчёт и экспорт для консоли; проверяет существование студента, собирает все результаты перед записью |
| Поведенческий | Strategy, `IFinalScorePolicy` | Пользователь выбирает, считать пропуски нулями или запрещать неполный итог; расчёт не зависит от меню |

Статический `RubricBuilder.Empty` нужен для начального незаполненного рубрикатора в
интерактивной сессии. Это не отдельный заявленный паттерн. Незавершённый рубрикатор
нельзя использовать для итога. Дополнительных иерархий фабрик и команд нет.

## Хранение и экспорт

Репозитории работают в памяти: после выхода данные исчезают. ТЗ не требует
восстанавливать сессию; для этого можно заменить адаптеры, не меняя Domain.
Приложение однопользовательское, многопоточность и транзакции БД не реализованы.
Изменение и удаление студентов/критериев не добавлены: обязательны добавление и список;
исправление и отмена оценок реализованы. Импорт не входит в обязательные сценарии.

CSV содержит `student_id,name,score,evaluated,total,policy`, кодировка UTF-8 с BOM,
разделитель — запятая, дробный разделитель — точка. Текстовые поля заключены в кавычки,
внутренние кавычки удваиваются. Директории создаются автоматически. Сначала считаются
все результаты; доменная ошибка не перезаписывает существующий файл. Ошибки доступа
и неверный путь показываются пользователю. Экспорт в существующий файл заменяет его.

## Проверка

25 тестов xUnit. `DomainTests` проверяет границы баллов, неизвестный критерий, исправление/отмену,
расчёт с разными максимумами, пропуски, неполный рубрикатор, веса, дубликаты и VO.
`ApplicationTests` проверяет полный сценарий через DI с CSV, неизвестного и повторного
студента, сохранность файла при ошибке и замену экспортёра тестовой реализацией.
